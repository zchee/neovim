# Symbols the nvim executable exports to code that is dlopened into it.
#
# Passed to ld64 as -exported_symbols_list; everything not named here becomes
# a private extern, which both shrinks the export table and lets LTO specialize
# and discard far more of the binary. Note that ld64 treats every entry as an
# initial undefine, so a name listed here that no longer exists is a link
# error, not a warning -- that is deliberate, it means an API that disappears
# out from under us fails loudly instead of shipping broken. Wildcards are the
# exception: a pattern that matches nothing is silently ignored, so they are
# used only where the exact spelling is expected to drift.
#
# What has to be here and why:
#   - the Lua 5.1 C API, which Lua C modules loaded through package.cpath
#     resolve against the host process (see neovim/neovim#25295)
#   - LuaJIT's own extensions to it, for modules built against LuaJIT
#   - luv's public C API from luv.h, for modules that integrate with the
#     event loop nvim already owns
#   - tree-sitter's allocator hooks, which parsers compiled with
#     TREE_SITTER_REUSE_ALLOCATOR expect to find in the host
#
# Nvim's own internals are deliberately absent: nothing dlopened into nvim is
# supposed to reach into them, and code that FFI'd into them (LuaJIT ffi.C on
# an nvim function) will no longer resolve. Build with -D ENABLE_EXPORTS=ON to
# get the old export-everything binary back.
#
# Regenerate the Lua entries from the headers nvim actually built against:
#   H=.deps/usr/include/luajit-2.1
#   grep -ohE '\b(lua_|luaL_)[A-Za-z0-9_]+' $H/lua.h $H/lauxlib.h | sort -u \
#     | comm -12 - <(nm -gU build/bin/nvim | awk '{print $3}' | sed 's/^_//' | sort -u)
# (the comm drops the macros and typedefs the grep also picks up), then the
# same for luaopen_* in lualib.h, luaJIT_* in luajit.h, and luv_* in luv.h.
